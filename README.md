# МИС для стоматологии — MVP (форма 058/у РК)

Минимальный прототип электронной мед. карты стоматологического пациента
по форме № 058/у (приказ и.о. МЗ РК № ҚР ДСМ-175/2020).

## Что умеет

- **Картотека пациентов** — поиск по ФИО / ИИН / телефону
- **Паспортная часть** (п. 1–10) — возраст считается автоматически от даты рождения
- **Клиническая часть** (п. 11–22) — все поля бланка
- **Зубная формула** — 32 зуба в нотации FDI, состояния O / R / C / P / Pt / П / A / K / И,
  цветовая раскраска: выбираете состояние, затем кликаете по зубам
- **Дневник приёмов** (п. 19) — каждый визит добавляет запись с датой, врачом, диагнозом
  и описанием проделанного
- **Файлы пациента** — фото, 3D/КЛКТ-снимки, рентген, документы (превью для картинок)
- **Печать** — форма 058/у в вёрстке бланка, скачивается как HTML → Ctrl+P → PDF

## Запуск локально

```
pip install -r requirements.txt
streamlit run app.py
```

Данные складываются в `data/` — `dental.db` (SQLite) и `data/files/` (загруженные файлы).

## Деплой на Streamlit Community Cloud

1. Создать репозиторий на GitHub и запушить эту папку.
2. Зайти на share.streamlit.io → **New app** → выбрать репозиторий, ветку и `app.py`.
3. В **Advanced settings → Secrets** вставить:
   ```
   APP_PASSWORD = "ваш-пароль"
   ```
4. Deploy.

## ⚠️ Ограничения этой версии

Это **демонстрационный прототип**, а не боевая система:

- **Нельзя вносить реальные данные пациентов.** ПДн граждан РК по закону
  «О персональных данных и их защите» должны храниться на серверах на территории
  Казахстана; Streamlit Community Cloud этому не соответствует.
- **Хранилище эфемерное.** На Streamlit Cloud файловая система сбрасывается при
  перезапуске приложения — база и загруженные файлы пропадут. Для боевой версии
  нужен внешний PostgreSQL + S3-совместимое объектное хранилище.
- Нет ролей и разграничения доступа, нет журнала действий (кто что менял),
  нет бэкапов, нет 3D/DICOM-просмотрщика (файлы только хранятся и скачиваются).
- Одна карта на пациента; история изменений по зубу не ведётся.
